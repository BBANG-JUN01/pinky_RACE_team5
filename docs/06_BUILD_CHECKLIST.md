# 구현 순서별 세부 체크리스트

일정은 2주 중 실작업 10일을 가정한 제안이다. D11~D14는 달력상 여유가 있을 때 재시험에 사용한다.
아래 시험 횟수는 제조사 보증이 아닌 팀의 초기 통과 목표다. 속도와 거리는 S01 실측 후 결정한다.

## A: 정찰과 주행
1. S00: scan 각도·단위, odom 방향, 로봇 footprint, TF 권한, 실제 명령 타입을 기록한다.
2. S02: 벽 추종 입력을 유효 거리 배열로 정리한다. 앞 장애물 감속, 코너 회전, 막힘 정지를 먼저 만든다.
3. 시작점 근접만으로 정찰 완료를 판단하지 않는다. 최소 이동 거리, 경과 시간, 주행 방향, 출발 영역 이탈 후 재진입을 결합한다.
4. SLAM loop closure 이후 지도와 경로 좌표가 일치하는지 확인한다. SLAM 종료와 localization 전환 사이에 주행을 정지한다.
5. S03: 벽 사이 주행 가능 영역을 추출하고 중심 경로를 생성한다. 재표본화·평활화 후 footprint와 벽 간섭을 다시 검사한다.
6. 지도, 경로, 구간, 체크포인트를 한 버전으로 확정한다. B에 실제 파일을 전송하고 해시와 localization 상태를 확인한다.
7. S04: 연속 경로를 Nav2 FollowPath로 전달하고 곡률에 따라 상한을 낮춘다. RPP부터 사용하며 실패 원인을 기록한 뒤 MPPI를 비교한다.
8. S09: 직선에만 좌우 후보 경로를 만든다. costmap과 상대 로봇의 예상 점유 영역을 검사한다. PASS/MERGE/취소를 명시적으로 분리한다.

## B: 인식
1. S00: 두 카메라의 topic, 크기, frame, stamp를 확인하고 같은 조명에서 샘플을 녹화한다.
2. 데이터셋은 사람, cone, bollard, robot, flag의 실제 촬영 예시를 확보한다. 깃발은 검출 후 색/무늬 분류로 나눠도 된다.
3. 학습용/검증용을 연속 영상의 인접 프레임으로 무작위 분할하지 않는다. 촬영 세션 또는 장면별로 분리한다.
4. 검출 결과에 class, confidence, bbox, 촬영 시각을 넣고 미검출과 오래된 결과를 구분한다.
5. 카메라-LiDAR 연관을 보정한다. bbox 크기만으로 실제 거리라고 단정하지 않는다. 연관 실패 시 distance_valid=false로 보낸다.
6. 사람은 위치와 진행 경로의 관계를 검사한다. 신규 위험은 즉시 정지 요청, 해제는 연속 유효 관측과 보호 구역 해소로 판단한다.
7. 옐로/그린은 깜빡임 방지 조건을 두되 레드 반응을 과도하게 지연시키지 않는다. flag 관측이 사라졌다고 정상 상태로 바꾸지 않는다.
8. 그리드 마커는 칸별 ID를 부여하고 접근 자세와 정렬 오차를 출력한다. 바닥 선만으로 칸 인식이 가능한지는 별도 실측한다.

## C: 경기·행동
1. race_id와 command_id를 생성하고 같은 명령의 재수신을 무시한다. 이전 경기 명령을 새 경기에서 적용하지 않는다.
2. 경기 생애, 경기 제한, 행동, 정지 사유를 별도 관리한다. 각 전환에 원인과 이벤트 시각을 로그로 남긴다.
3. 그리드 준비는 A/B pose_valid, 동일 map/path 버전, 정렬 완료, 위험 없음이 모두 성립해야 승인한다.
4. 출발등은 red를 확인한 후 소등 전이를 인식한다. 카메라가 끊겨 어두워진 상황을 소등으로 인정하지 않는다.
5. 랩은 순서 있는 체크포인트와 방향 판정을 거쳐 finish에서만 증가한다. 선 주변 떨림은 재통과로 세지 않는다.
6. 랩 계시는 중앙 단일 기준을 사용한다. 표시 장치는 수신 값으로 화면을 갱신하며 별도 공식 기록을 생성하지 않는다.
7. 페널티는 실제 정지가 확인된 뒤 연속 정지 시간을 잰다. 움직이면 계시를 재시작한다. 종료 시 PENALTY 사유만 해제한다.
8. SC 발동 당시 순서를 저장하고 추월을 금지한다. 상대 위치가 오래되면 추정 속도로 계속 추종하지 않는다.
9. DRS는 검출선 자격과 사용 구간을 분리한다. 앞차 식별, 같은 진행 방향·경로 진행 거리, 데이터 유효성을 확인한다.
10. 아이템/코너 보상은 기존 speed policy에 요청을 추가하는 방식으로 붙인다. 최종 guard를 우회하지 않는다.

## D: 통합·운영·표시
1. 로봇별 namespace와 frame prefix를 고정한다. namespace만으로 TF frame 충돌이 해결되지는 않는다.
2. arbiter는 정찰/그리드/경기 중 하나만 선택한다. 전환 시 이전 source를 취소하고 0 명령 확인 후 다음을 활성화한다.
3. 로컬 timer가 마지막 명령·센서·관제 heartbeat 나이를 검사한다. 통신 단절 시 PC가 정지 명령을 보내줄 것이라고 가정하지 않는다.
4. 대시보드에 phase, restriction, stop 이유, lap, last/best, heartbeat 나이, map/path 버전, 최신 명령 수신 여부를 표시한다.
5. 조작은 전체 RED, 개별 ESTOP, 개별 페널티, SC 요청을 구분한다. GREEN이 개별 정지를 풀지 않도록 한다.
6. LED/LCD 드라이버를 추상 상태 출력에 연결한다. DRS 초록은 자격 획득이 아닌 실제 추가 출력 시에만 켠다.
7. 화면 갱신은 주행 제어를 막지 않게 별도 timer로 수행한다. 정상 화면은 LAP/현재/이전/BEST/순위, 정지 시 원인을 우선한다.
8. 배포 설정·모델·지도·실행 명령을 버전으로 묶고 최종 시연 전 변경을 동결한다.

## 초기 통과 목표
| 시험 | 제안 목표 | 기록 |
|---|---|---|
| 단독 주행 | 연속 3랩, 사람 수동 조작 0회 | 접촉·경로 이탈·실패 원인 |
| 기본 경기 | 정찰부터 종료까지 3회 연속 | 자동 정렬 성공, 오출발, 랩 오계수 |
| 깃발 | 종류별 10회 + 가림/잘못된 입력 | 인식부터 최종 명령까지 지연 |
| 사람/장애물 | 위치를 바꿔 각 10회 | 정지 거리·회피 성공·통로 막힘 |
| 페널티 | 중첩 정지 포함 10회 | 실제 정지 시작/종료와 유지 사유 |
| DRS | 허용 10회와 차단 조건별 반복 | 요청/허용/최종 상한/LED 일치 |
| 통신 단절 | 관제·카메라·scan 별도 반복 | 마지막 수신부터 실제 정지까지 |

D8까지 기본 경기의 반복 성공이 확보되지 않으면 새 기능보다 실패 재현과 수정에 시간을 배정한다.
요구사항을 보류할 때는 DECISIONS에 이유, 영향, 재개 조건을 남긴다.
