# 단계별 완료 기준과 증거

단계 통과는 코드 존재가 아니라 검증 증거로 판단한다. 각 단계의 작업은 progress/tasks.json에 연결한다.

## S00 장비와 데이터 계약
- 목표: D1; 담당: D; 선행 검증: 없음
- 작업: A의 센서 조사 / B의 카메라 조사 / C의 상태 정의 / D의 연결 조사
- 통과: 두 대 토픽·TF·명령 형식·버전·시각 확인
- 증거: evidence/S00/result.md와 입력 bag 또는 영상의 위치·버전·실행 명령. 파일 경로를 result.md에 기록.
- 실패 시: 실패 입력을 보존하고 BLOCKED로 변경한다. 임시 수동 개입을 자동 성공으로 기록하지 않는다.

## 상태 의미

| 상태 | 의미 |
|---|---|
| TODO | 개발 전 |
| ACTIVE | 구현 중 |
| BLOCKED | 필요한 입력 또는 결함으로 중단 |
| REVIEW | 코드와 자체 시험 완료, 통합 확인 대기 |
| VERIFIED | 담당 외 1명 확인과 단계 증거 확보 |

VERIFIED의 최종 판정은 팀 검토다. CLI는 파일 존재와 선행 단계를 검사할 뿐 영상·로그의 성공 여부를 판독하지 않는다.
S12는 선택 기능이므로 필수 완료율의 분모에서 제외한다. 단계별 4개 작업이 모두 VERIFIED면 해당 단계가 통과다.
