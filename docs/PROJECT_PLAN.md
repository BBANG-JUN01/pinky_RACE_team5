Pinky GP   기능 설계와 2주 개발 실행 계획

버전 1.2  \|  작성일 2026년 11월 17일  \|  4인 팀  \|  Pinky Pro 2대

우리 팀은 사전 지도가 없는 벽형 트랙에서 정찰랩으로 지도를 생성한 뒤, 두 로봇이 자동으로 출발 그리드에 정렬하고 경기를 수행하는 시스템을 개발한다. 경기 중 임의로 등장하는 장애물과 사람을 인식하고, 깃발과 경기 상태에 따라 경로와 속도를 변경한다.

본 문서는 구현 범위, 주행 알고리즘 시험안, 경기 규칙, 소프트웨어 구조, 담당자 산출물, 10일 로드맵과 검증 기준을 정의한다. 실제 F1 규정의 복제가 아니라 F1에서 착안한 자체 경기 규칙을 사용한다.

개발의 핵심 결정

정찰로 생성한 지도와 기준 경로를 경기에서 사용한다. 매 경기의 정찰은 기존 지도를 불러오는 방식으로 대체하지 않는다.

레드 플래그는 해당 경기 종료다. 그린은 옐로와 세이프티카 제한만 해제한다.

정찰은 경계 추종, 경기 주행은 Pure Pursuit 계열을 먼저 시험한다. 장애물 회피와 추월 경로 판단은 별도로 구현한다.

5일 차에 기본 경기 통합, 8일 차에 기능 범위 동결을 목표로 한다. 아이템과 코너링 보상은 마지막에 추가한다.

확장 기능과 제외 범위

아이템 2종인 부스터와 상대 감속, 코너링 에너지 보상을 확장 기능으로 보관한다. 더블 옐로, 블루, 흑백 경고기, 블랙 플래그, 피트 운영, 트랙 리밋 페널티는 제외한다. 벽 충돌은 운영자가 정지 페널티를 부여할 수 있다. 후면 LED와 전면 LCD로 경기 상태를 표시하는 기능을 추가한다.

일반 주행과 물체 검출만 성공한 경우를 전체 프로젝트 완료로 보지 않는다. 정찰 지도에서 경기를 재현하는 통합 경로가 필수다.

2 경기 시나리오와 상태

| 단계 | 주요 동작 | 다음 단계 조건 |
| --- | --- | --- |
| 준비 | 센서, 시간, 통신, 정지 기능 확인 | 두 대 상태 정상 |
| 정찰 | 저속 경계 추종과 SLAM 및 궤적 기록 | 복귀 판정과 지도 검사 |
| 경로 준비 | 폐곡선 경로, 진행 좌표, 구간 생성 | 벽 간섭과 경로 연결 확인 |
| 그리드 | 로봇별 출발 칸 접근과 정밀 정렬 | 두 대 GRID_READY |
| 출발 | 출발등 점등과 소등 관측 | 경기 허가와 유효 소등 |
| 경기 | 추종, 추월, 깃발과 랜덤 이벤트 대응 | 완주 또는 레드 |
| 정상 종료 | 체커 적용 후 로봇별 완주와 정차 | 전체 결과 확정 |
| 중단 종료 | 레드에 따른 정지 유지 | 새 경기 초기화만 허용 |

상태를 분리하는 원칙

경기 생애 상태는 IDLE, CHECKING, RECON, MAP_READY, GRID_ALIGN, STARTING, RACING, FINISHING, FINISHED, ABORTED로 구성한다. RACING 안의 경기 제한은 NORMAL, YELLOW, SC로 별도 관리한다. 사람 정지와 페널티는 개별 로봇의 정지 사유로 유지한다.

그린으로 NORMAL이 되어도 개별 정지 사유가 남아 있으면 이동하지 않는다. 레드는 생애 상태를 ABORTED로 전환하므로 이후 그린을 받아도 반응하지 않는다. 비상 정지 해제와 새 경기 초기화는 운영자 명시 명령으로만 수행한다.

이벤트 처리

모든 경기 명령에는 race_id, command_id와 발생 시각을 포함한다. 중복 명령은 다시 실행하지 않는다.

같은 처리 주기에 그린과 레드가 들어오면 레드가 우선한다. 그린은 현재 제한 시작 이후 관측된 이벤트만 인정한다.

정찰 및 정렬 중에는 DRS, 아이템, 랩 기록을 비활성화한다. 로봇별 완주 후에도 다른 로봇의 경기는 계속할 수 있다.

3 정찰랩과 지도 생성 설계

기본 제안은 A의 단독 정찰 후 B에 지도와 경로를 공유하는 방식이다. A와 B가 각각 정찰하는 방식은 순차 실행으로 확장할 수 있다. 두 대의 독립 SLAM 지도를 실시간 병합하는 기능은 기본 범위에 포함하지 않는다.

정찰 알고리즘

라이다 전방과 좌우 영역의 유효 거리값을 사용해 벽과의 간격을 유지한다. 평활화한 측면 거리 오차와 진행 방향을 이용해 선속도와 각속도를 출력하고, 전방 공간이 줄면 먼저 감속한다. 벽 추종 PID를 기본으로 시험하고, 장애물이 있는 정찰을 허용해야 할 경우 Follow the Gap을 비교한다.

정찰 중에는 경기용 랜덤 물체를 투입하지 않는 것을 기본 운영 규칙으로 한다.

속도 명령, 라이다, 오도메트리, IMU, TF와 SLAM 결과를 함께 기록한다.

정찰 시간 초과, 센서 이상, 루프 탈출, 반복 정체 시 정지하고 원인을 보고한다.

정찰 완료는 시작 표식 재발견, 최소 이동량, 출발 구역 이탈 후 재진입, 진행 방향을 함께 확인한다.

지도와 궤적의 확정

루프 폐쇄 과정에서 map 좌표가 보정될 수 있으므로 주행 중 map 좌표를 단순 연결한 기록을 그대로 최종 경로로 사용하지 않는다. 최종 지도에서 통로 중심을 추출하거나 보정된 궤적을 재구성한 뒤, 간격 재표본화와 평활화를 수행한다. 이 부분은 D3의 주요 기술 검증 대상이다.

| 검사 | 통과 조건 |
| --- | --- |
| 지도 연결 | 안쪽과 바깥쪽 벽이 과도하게 겹치지 않고 순환 통로가 연결됨 |
| 경로 유효성 | 전체 경로에서 로봇 외곽과 설정 여유가 벽을 침범하지 않음 |
| 루프 연결 | 경로 끝과 시작의 위치 및 방향이 연속적임 |
| 두 대 공유 | 같은 지도 버전과 좌표 기준을 사용함 |
| 확정 절차 | 관제에서 지도 검사 후 경기 준비 승인 |

운영자의 지도 확인은 자동 지도 생성의 실패를 숨기기 위한 수동 재작성과 구분한다. 수동 수정이 필요했다면 수정 내용과 이유를 시험 기록에 남긴다.

4 기존 레이싱 알고리즘 도입안

새로운 주행 제어기를 처음부터 만드는 대신 공개 알고리즘을 먼저 시험한다. F1TENTH 교육자료는 Follow the Gap과 Pure Pursuit를 제공한다. 차량용 조향 명령을 그대로 사용하는 코드는 핑키프로에 바로 적용하지 않고, 실제 구동 인터페이스와 운동학에 맞춰 수정한다. [S3]

| 후보 | 장점과 제한 | 프로젝트 결정 |
| --- | --- | --- |
| 벽 추종 PID | 지도 없이 시작 가능. 벽 형상과 코너에서 조정 필요 | 정찰 기본안 |
| Follow the Gap | 라이다의 빈 공간을 선택. 랩 경로와 경기 규칙은 보장하지 않음 | 정찰 또는 반응형 회피 비교안 |
| Adaptive Pure Pursuit 및 RPP | 기준 경로 추종과 곡률 기반 감속. 단독으로 우회 경로를 만들지 않음 | 경기 기본 제어 후보 |
| Nav2 MPPI | 후보 운동 궤적 평가와 장애물 대응. 연산과 설정 검증 필요 | D3까지 짧은 비교 시험 |
| 최소 곡률 최적화 및 MPCC | 레이싱 경로 최적화 가능성이 있으나 모델과 추가 구현 필요 | 2주 기본 범위 제외 |

우선 시험할 조합

정찰은 벽 추종 PID와 SLAM Toolbox, 경기 위치 추정은 AMCL, 경기 추종은 Nav2 Regulated Pure Pursuit를 우선 시험한다. 로컬 우회와 추월은 충돌 검사한 후보 경로를 별도로 만들어 제어기에 전달한다. RPP는 경로를 따라가는 역할이며 동적 우회 전체를 해결하는 것으로 설명하지 않는다. [S4, S5]

회피 경로 생성 부담이 크거나 추종 성능이 부족하면 MPPI를 같은 조건으로 비교한다. MPPI를 선택해도 전역 경로와 트랙 제한이 필요하며, 제자리 고속 회전이나 역주행이 나오지 않도록 설정한다. D3 종료까지 기본 제어기를 하나로 확정한다. [S6]

비교 시험과 채택 기준

동일한 지도, 코스, 속도 상한에서 단독 완주와 콘 회피를 반복한다.

완주율, 경로 오차, 접촉, 불필요한 정지, 제어 주기 지연과 CPU 사용량을 비교한다.

연산이 밀리거나 회피 중 반복 진동이 발생하면 속도를 낮추고 원인을 확인한다.

코드 라이선스, 사용 버전과 수정 내용을 기록한다. 기존 알고리즘 사용과 직접 구현한 판단 로직을 구분한다.

5 경기 경로와 추종 및 추월

순환 경로 표현

기준 경로를 일정 간격 점들의 폐곡선으로 표현한다. 각 점에 누적 거리 s, 진행 방향, 곡률, 경계까지 여유와 구간 ID를 부여한다. 순위와 DRS 간격은 같은 경로 기준으로 계산한다. 곡선 반대편 로봇을 앞차로 오인하지 않도록 진행 방향과 구간 연결성을 함께 확인한다.

현재 위치를 경로에 투영할 때 직전 진행 구간 주변을 우선 탐색한다. 헤어핀에서 가장 가까운 다른 구간으로 점프하면 랩과 순위가 바뀔 수 있다. 큰 위치 점프는 경기 진행값에 즉시 반영하지 않고 유효성을 재확인한다.

속도와 경로 추종

기본 속도는 곡률과 전방 여유에 따라 설정한다. 허용 횡가속도를 사용하는 경우 v ≤ sqrt(a_lat_max / max(abs(kappa), epsilon))를 초기 설계식으로 사용할 수 있으나, a_lat_max는 실측으로 정한다. 추가 출력도 하드웨어와 경로의 속도 제한을 넘지 못한다.

추월 동작

| 상태 | 진입과 행동 | 이탈 조건 |
| --- | --- | --- |
| FOLLOW | 앞차와 간격 유지 | 허용 직선과 추월 필요 |
| CHECK | 옆 경로와 합류 구간의 점유 검사 | 전체 후보 경로 유효 |
| PASS | 추월 경로 추종, 상대 위치 확인 | 종방향 간격 확보 |
| MERGE | 충돌 검사한 경로로 기본선 복귀 | 기본 경로 안정 진입 |
| ABORT | 현재 공간에서 감속 또는 정지 | 안전한 재계획 가능 |

첫 구현은 넓은 직선에 기본선과 추월선 두 후보를 생성한다. 모든 오프셋 경로는 벽과 장애물 간섭을 검사한다. 단순 평행 이동만으로 코너 경로를 만들지 않는다. 선행 로봇은 추월 도중 임의로 진로를 막지 않는 자체 규칙을 사용한다.

추월 취소는 강제 원위치 복귀를 뜻하지 않는다. 복귀 경로가 막혀 있으면 현재 경로에서 감속하거나 정지한다. 반복 좌우 변경을 막기 위해 경로 선택 유지 시간과 재시도 대기 시간을 설정한다.

6 출발 그리드와 신호등

자동 그리드 정렬

두 출발 칸은 같은 출발선에 나란히 배치한다. 정찰 출발 기준 표식을 지도에 연결하고, 칸별 식별 마커 또는 검출 가능한 바닥 선으로 목표 위치와 방향을 얻는다. 목표 근처까지 지도 기반으로 접근한 뒤 저속 영상 정렬로 마무리한다.

| 단계 | 기능 | 실패 시 처리 |
| --- | --- | --- |
| 구역 확인 | 출발 기준 표식과 지도 위치 연결 | 정렬 시작 보류 |
| 칸 배정 | A와 B에 서로 다른 칸 ID 할당 | 중복 배정 차단 |
| 접근 | 한 대씩 그리드 접근 | 상대 경로 점유 시 대기 |
| 정밀 정렬 | 바닥 선 또는 마커로 위치와 방향 조정 | 관측 실패 시 정지 |
| 준비 완료 | 오차와 정지 상태 확인 후 GRID_READY | 준비 해제 후 재정렬 |

카메라가 바닥 선을 볼 수 있는지 D1에 확인한다. 보이지 않는 위치의 선을 전제로 개발하지 않는다. 마커 크기, 장착 위치와 카메라 캘리브레이션은 실제 영상으로 검증하며, 두 칸의 접근 경로가 벽과 겹치지 않게 한다.

출발등 판정

신호등은 실제 LED 장치 또는 화면으로 구현할 수 있다. 관제는 적색등 순차 점등과 전체 소등을 제어하고, 로봇은 영상에서 점등 순서와 정상 소등을 확인한다. 신호등 영역이 사라지거나 영상이 오래되면 출발하지 않는다.

출발 조건은 두 대 정렬 완료, 현재 경기 STARTING, 유효한 점등 과정, 새 소등 관측을 모두 만족하는 것이다.

카메라 주기와 통신 지연 때문에 두 대의 출발 시각이 달라질 수 있다. 공정성을 위해 중앙 승인과 로봇별 시각을 기록한다.

영상 판정 실패 시 자동 재출발하지 않는다. 운영자가 출발 절차를 취소하고 다시 준비한다.

신호등만 끄고 즉시 다시 켜는 시험, 가림, 조명 변화, 연결 끊김을 음성 시나리오로 검증한다.

| --- | --- | --- |

모델과 데이터

사람 등 기본 모델의 클래스는 먼저 실제 카메라에서 시험한다. 상대 핑키프로, 깃발, 콘과 볼라드는 필요 시 추가 학습한다. 바닥 높이, 거리, 각도, 조명, 가림, 물체가 없는 장면을 포함하고 연속 영상의 유사 프레임이 학습과 시험에 섞이지 않도록 촬영 세션 단위로 분리한다.

YOLO는 객체 영역을 검출하고, 출발등 점등 개수와 깃발 색상 보조 판정은 영역 안의 영상 처리로 분리할 수 있다. 그리드는 의미 검출보다 식별과 정렬이 중요하므로 ArUco를 사용하는 것을 기본 제안으로 한다. [S2, S7]

거리와 위치 해석

단안 YOLO 박스만으로 정확한 거리를 확정하지 않는다. 카메라 내부 파라미터와 라이다 외부 좌표 관계를 확인해 영상 방향과 스캔을 연결한다. 두 센서는 높이가 달라 같은 물체를 보지 못할 수 있으므로 연관 실패와 거리 유효성을 별도 출력한다.

거리 연관이 불확실한 사람 후보가 주행 방향에 있으면 보수적으로 감속 또는 정지한다. 라이다 스캔 높이에 걸리지 않는 낮은 물체는 실제 검출 시험으로 확인하고 허용 투입 물체 목록을 정한다. 외부 로봇 위치 공유도 현장 센서를 대체하지 않는다.

시간과 연산

촬영 시각을 유지하고 최신 프레임을 우선 처리한다. PC 추론 지연을 측정하며, 영상 장애 시 로봇 자체 정지 계층을 유지한다. 실제 SBC 모델과 처리량은 D1에 확인한다.

8 깃발과 세이프티카 운영

| 이벤트 | 경기 규칙 | 해제 조건 |
| --- | --- | --- |
| YELLOW | 전체 감속, 추월 금지, DRS 해제 | 제한 시작 이후 유효 GREEN |
| GREEN | YELLOW 또는 SC에서 NORMAL 복귀 | 다음 제한 이벤트 |
| RED | 전체 ABORTED, 정지, 효과 취소 | 해제 없음, 새 경기 초기화 |
| CHECKER | 완주 신호 활성화, 유효 결승선 통과 로봇 종료 | 경기 초기화 |
| SC ON | 감속, 현재 순서 유지, 추월과 DRS 금지 | 새 유효 GREEN |

깃발 인식의 적용

초기 구현은 전체 경기 공통 신호로 운영한다. 한 대의 유효한 인식 이벤트를 경기 관리자가 확인해 두 대에 전파한다. 단일 프레임 오검출을 줄이기 위한 신뢰도와 연속 확인 조건을 두되 정지 반응 지연도 측정한다. 반복 검출은 동일 상태를 재시작하지 않는다.

SC에서 옐로를 봐도 SC 순서 유지 규칙은 유지한다. 그린은 옐로와 SC만 해제한다. 사람, 페널티, 비상 상태, 레드 종료는 해제하지 않는다. GREEN은 해당 깃발 이벤트의 시각으로 오래된 관측을 배제한다.

세이프티카 상황

별도 세이프티카 로봇은 사용하지 않는다. 관제의 SC ON으로 진입하는 것을 기본으로 하고, SC 표식 영상 인식은 확장할 수 있다. 진입 시 유효한 순위를 기록하고 선행은 제한 속도로 주행하며 후행은 간격을 유지한다.

그린 이후 정상 속도로 점진적으로 복귀한다. 이전 DRS 자격은 복원하지 않고 다음 검출선에서 다시 판단한다.

SC 중 전방에 사람이 있거나 통로가 막히면 두 대 모두 필요한 정지를 수행한다.

추월 도중 SC가 발생하면 즉시 무리하게 순서를 되돌리지 않는다. 안전한 감속 후 순위가 안정된 시점에 순서 재설정 또는 운영자 판정을 수행한다.

SC 중 앞차가 페널티로 정지하면 후행도 대기한다. 운영자는 정체가 해소되지 않으면 레드로 종료할 수 있다.

9 랜덤 장애물과 사람 대응

운영자는 경기 중 지정 이벤트 구역 안의 위치와 시점을 자유롭게 선택해 물체를 투입한다. 로봇에 사전 위치를 알려주지 않는다. 투입 가능한 최소 거리는 감지 지연, 정지 거리와 여유를 실측해 정한다. 초기 시험은 던지기보다 바닥에 놓는 방식으로 수행한다.

| 상황 | 로봇 동작 | 완료 기준 |
| --- | --- | --- |
| 콘 또는 볼라드 | 현재 경로 점유와 통과 공간 확인 후 우회 | 벽과 물체 접촉 없이 본선 복귀 |
| 사람 접근 | 주행 보호 구역 진입 시 정지 | 정지 지연과 거리 기록 |
| 물체 제거 | 지속적인 자유 공간 관측 후 재계획 | 유령 장애물 없이 재출발 |
| 전체 통로 차단 | 정지하고 BLOCKED 보고 | 억지 통과와 벽 외부 우회 없음 |
| 미분류 근접 물체 | 라이다 등으로 감속과 정지 | YOLO 분류 대기 중 충돌 방지 |
| 관측 끊김 | 센서별 신선도 확인 후 제한 | 새 관측 없이 정상 복귀하지 않음 |

정적 지도와 동적 장애물

정찰 종료 후 지도는 기준으로 고정한다. 경기 중 장애물은 로컬 및 필요한 글로벌 장애물 계층에서 갱신하고 관측된 자유 공간으로 해제한다. 사람이 서 있던 위치를 영구 벽으로 남기지 않는다. 로컬 회피 후보 전체가 벽 안에 있는지 검사하고 임의 역주행은 허용하지 않는다.

사람 정지와 재출발

카메라에 보이는 모든 사람을 정지 대상으로 삼으면 관객 때문에 경기가 멈출 수 있다. 현재 진행 경로와 확장 보호 구역에 연관된 사람을 대상으로 한다. 영상 거리 연관이 불확실하면 감속하고 확인한다. 재출발에는 보호 구역 비움, 유효 센서, 다른 정지 사유 없음과 출발 가능한 앞 간격이 필요하다.

정지 설계

속도 v, 총 반응 지연 T, 측정 제동 감속도 a를 사용할 때 vT + v²/(2a)를 기초 정지 거리 추정에 참고한다. 실제 바닥 마찰과 모터 응답으로 측정한 최악값에 여유를 추가해 보호 구역을 정한다. 이 식만으로 사람 투입 거리를 확정하지 않는다.

10 DRS와 페널티 및 확장 기능

DRS형 추격 보조

지정 검출선을 지날 때 같은 진행 방향의 앞차와 트랙 거리 차이가 임계값 이내이면 자격을 부여한다. 기본은 거리 기준이며, 시간 기준은 같은 검출선 통과 시각 차이로 별도 구현한다. 사용 직선 안에서 공간과 경기 조건이 유효할 때 속도 상한을 높인다.

자격과 활성 상태를 분리하고, 추월 경로가 없으면 DRS가 활성 가능해도 앞차를 밀어붙이지 않는다.

같은 랩의 앞차 여부와 순환 거리 차이를 구분한다. 옆 통로 또는 헤어핀 반대편 차는 대상이 아니다.

코너, 사람, 충돌 위험, 옐로, SC, 레드, 페널티에서 즉시 추가 출력 해제.

구간 종료 시 자격 소진. 그린 이후 다음 검출선에서 재판정. 기본 속도를 하드웨어 최대치보다 낮게 잡아 추가 출력 여유를 확보한다.

외부 정지 페널티

관제에서 로봇 ID, 정지 시간과 사유를 지정한다. 로봇은 제어된 정지를 수행하고 실제 속도가 정지 기준 아래로 안정된 시점부터 계시한다. 종료 시 페널티 사유만 해제하고, 현재 경기 제한과 주변 상황을 다시 확인한다. 타이머가 직접 전진 명령을 내리지 않는다.

활성 페널티 중 중복 명령은 재적용하지 않는다. 새로운 추가 페널티는 자동 중첩하지 않고 운영자가 남은 시간을 확인해 별도 승인하도록 한다. 레드가 발생하면 페널티 진행보다 경기 종료가 우선하며 새 경기로 타이머를 넘기지 않는다.

최후순위 확장

| 기능 | 동작 | 제약 |
| --- | --- | --- |
| 부스터 아이템 | 접근과 연속 인식으로 획득 | 물리 접촉으로 획득하지 않음 |
| 상대 감속 | 중앙 승인 후 상대 속도 상한 감소 | 강제 급제동과 무한 중첩 없음 |
| 코너링 에너지 | 이동과 정상 코너 통과로 적립 | 제자리 회전과 충격 제외 |

아이템 ID, 획득 승인, 소진과 재배치 처리는 중앙에서 관리한다. 아이템과 DRS를 함께 사용할 경우 기본안은 출력 중첩 금지다. 코너 G 초과 즉시 가속 대신 정상 코너 통과 후 직선에서 쓸 수 있는 보상을 지급한다.

경기 관리자는 규칙과 효과를 결정하고, 로봇별 제어는 경로 추종과 현장 정지를 수행한다. 정지 사유가 하나라도 남으면 정지하며, 중앙 PC 장애 시 계속 달리지 않는다. 로봇의 heartbeat timeout과 명령 timeout을 별도로 둔다.

최종 속도 명령

로봇별 최종 모터 명령 발행자는 하나로 제한한다. 경로 제어기가 만든 명령에 상한을 적용하고, 가감속을 정리한 뒤 최종 충돌 정지 검사를 수행한다. 최종 정지 이후의 단계가 명령을 다시 증가시키지 않게 한다. 정찰과 그리드 제어도 명시적인 제어권 전환으로 연결한다.

| 순서 | 우선 적용 조건 |
| --- | --- |
| 1 | 비상 정지, 센서 또는 명령 timeout, 근접 충돌 위험 |
| 2 | 레드 종료, 사람 정지, 개별 페널티 등 정지 사유 |
| 3 | 완주 후 종료 절차 또는 준비 단계 제한 |
| 4 | SC와 옐로 속도 및 추월 제한 |
| 5 | 앞차, 장애물, 곡률, 하드웨어 상한 |
| 6 | 정상 속도와 DRS 및 확장 효과 |

연결과 좌표 기준

로봇별 이름 공간과 프레임을 분리하고 공통 map에서 위치를 비교한다. 예시는 /robot_a와 /robot_b이며 센서의 실제 토픽 이름과 Twist 형식은 설치된 패키지에서 확인한다. 네임스페이스만 추가하면 TF 충돌까지 자동 해결되는 것으로 가정하지 않는다.

지도 파일과 좌표 원점, 기준 경로 버전이 두 대에서 같아야 한다. pose를 다른 ROS 도메인 사이에서 연결하는 경우 명시적인 브리지와 명령 확인 절차가 필요하다. 같은 도메인과 네임스페이스 구성을 기본 비교안으로 사용하되 현장 네트워크 정책에 맞춘다.

PC와 로봇의 시각 오차를 확인하고, 수신 시각과 촬영 시각을 구분한다. 오래된 명령과 검출은 무효 처리한다. 준비, 출발, 레드, 페널티 명령은 수신 확인과 상태 보고를 연결한다.

관제 화면

상단에는 경기 상태, NORMAL 또는 YELLOW 또는 SC, 경과 시간과 연결 상태를 표시한다.

중앙 지도에는 두 로봇, 기준선과 추월선, 체크포인트, DRS 구역, 그리드와 종료 위치를 표시한다.

로봇별 카드에는 랩, 순위, 실제 속도, 상한, DRS 자격과 활성, 페널티 남은 시간, 정지 사유를 표시한다.

두 카메라 영상과 이벤트 타임라인을 함께 제공한다. 어떤 로봇의 직접 인식으로 상태가 바뀌었는지 표시한다.

운영 버튼은 정찰 시작, 지도 승인, 정렬, 출발 절차, SC ON, 개별 페널티, 레드 종료, 비상 정지, 새 경기 초기화로 구성한다.

작업 의존관계

A의 센서와 수동 주행 → 정찰 → 지도와 경로 → 경기 추종이 주 경로다. D는 초기부터 두 대 실행과 TF 분리를 담당한다.

B의 검출 이벤트 형식 → C의 경기 전환이 연결된다. C는 B 모델 완성 전 가짜 이벤트로 개발한다.

B의 그리드 상대 위치 → D의 정렬 흐름 → A의 지도 기반 접근을 연결한다.

D의 상대 pose와 경로 진행 좌표 → C의 앞차 및 DRS 판정 → A의 추종 경로에 연결한다.

추월 판단은 C, 후보 경로 주행은 A가 담당한다. 인터페이스 경계에서 공동 시험한다.

| B | 카메라 시야 측정, 사람 기본 검출 시험, 깃발과 로봇 영상 수집, 표식 시험 |

협업 규칙

공통 저장소에 패키지와 설정을 모으고 로봇별 차이는 설정 파일로 관리한다. 매일 동작하는 기준 브랜치를 유지한다. 설정 변경도 변경 이유와 시험 결과를 남긴다. 매일 짧은 회의에서 완료, 막힘, 필요한 상대 입력만 공유하고 종료 전 최소 한 번 실물 통합한다.

장착물과 바퀴 상태, 배터리, 벽 고정과 바닥 마찰, 사람 접근 위치를 확인한다.

센서와 시각, 두 대 통신, 제어 명령 timeout과 비상 정지를 시험한다.

새 race_id 생성과 기존 정찰 지도 미사용을 확인하고 정찰을 시작한다.

지도와 경로 검사 후 로봇을 그리드에 자동 정렬한다. 출발등과 깃발 시야를 확인한다.

경기 중과 종료

운영자 한 명은 깃발과 SC 및 페널티를, 다른 한 명은 랜덤 물체 배치를 맡는다. 같은 사람이 관제와 물체 투입을 동시에 무리하게 수행하지 않는다. 이벤트 시각을 기록하고 정체 또는 이상 동작이면 레드나 비상 정지로 종료한다.

정상 종료 후 로그와 설정 버전을 저장한다. 오류가 발생하면 입력과 상태를 먼저 보존하고 재시작한다. 레드 종료에서는 그린으로 재개하지 않고 초기화한다. 재시연에 수동 지원이 들어갔다면 지원 내용을 기록한다.

19 후면 LED와 전면 LCD 표시

후면 LED는 멀리서도 구분되는 주행 상태를, 전면 LCD는 상태 이름과 원인을 표시한다. DRS 활성 시 후면 LED를 초록색으로 켠다. 표시값은 명령 요청이 아니라 실제 적용된 경기 상태와 속도 제한을 기준으로 갱신한다.

| 상태 | 후면 LED 제안 | 전면 LCD 제안 |
| --- | --- | --- |
| 정찰 | 청색 느린 점멸 | RECON 및 정찰 경과 시간 |
| 그리드 이동과 준비 | 청색 점등 및 준비 시 흰색 | GRID 1 또는 2, READY |
| 출발 대기 | 흰색 점등 | WAIT 또는 출발등 점등 상태 |
| 정상 주행 | 낮은 밝기의 흰색 | 순위와 랩, 현재 랩 시간 |
| DRS 자격 보유 | 기본 표시 유지 | DRS READY |
| DRS 실제 활성 | 초록색 점등 | DRS ON 및 활성 상태 |
| 옐로 | 황색 점멸 | YELLOW 및 추월 금지 |
| 세이프티카 | 황색 느린 점멸 | SC 및 추월 금지 |
| 사람 감지 정지 | 적색 점등 | STOP 및 PERSON |
| 외부 페널티 | 자주색 점등 | PENALTY 및 남은 정지 시간 |
| 레드 종료 | 적색 점등 | RED 및 RACE ABORTED |
| 완주 후 정차 | 주행 중 기본 표시, 정차 후 흰색 점멸 | FINISHED, 순위와 기록 |
| 센서 및 통신 이상 | 적색 점등 | FAULT 및 센서 또는 통신 원인 |

표시 의미와 적용 범위

그린 플래그가 보였다는 이유로 후면 LED를 초록색으로 유지하지 않는다. 초록색은 DRS 추가 출력이 실제 허용된 상태에만 사용한다. 그린 해제는 LCD에 짧게 알리고 현재 주행 표시로 돌아간다. 제동과 추월 방향 표시는 LED 배치 확인 후 확장한다.

LED 개수, 후면에서의 가시성, LCD에서의 글자 크기는 실물에서 확인한다. 처음에는 전체 LED 단색과 정적 LCD 화면으로 구현하고, 복잡한 애니메이션은 추가하지 않는다. 표의 색상과 점멸 주기는 설계 제안이다.

20 표시 제어와 개발 검증

상태 우선순위와 일치

표시 우선순위는 비상 또는 장치 이상 → 레드 종료 → 사람 및 충돌 위험 정지 → 페널티 → 종료 절차 → SC → 옐로 → DRS 활성 → 일반 주행 및 준비 순서다. 여러 정지 사유가 있으면 LCD에 최우선 원인을 크게 표시하고 나머지는 보조 문구로 제공한다.

DRS 자격만 있거나 구간 진입을 기다리는 동안 초록색을 켜지 않는다. 앞차 또는 코너 제한으로 추가 출력이 억제되면 DRS LIMITED를 표시하고 LED는 기본 상태로 복귀한다. DRS가 끝나도 관성으로 속도가 남는 상황은 활성 효과와 구분한다.

제어 노드와 데이터

로봇마다 display_manager를 두고 MotionStatus, RaceControl, RaceProgress, EffectState를 읽어 LED와 LCD를 함께 갱신한다. 추가 필드는 display_state, primary_reason, drs_eligible, drs_active, penalty_remaining, lap, rank와 데이터 유효 시각이다. 표시 노드는 모터 명령을 발행하지 않는다.

출력은 로봇별 한 노드가 소유한다. 시작 제안은 상태 변화 즉시 표시, LED 갱신 최대 10Hz, LCD 숫자 갱신 최대 2~5Hz다. 동일 화면 재전송은 생략하고 정적 이미지를 캐시한다. 이 주기는 실제 처리 지연을 보고 조정한다. 오래된 상태에서는 초록색을 유지하지 않는다.

역할과 일정 반영

C는 우선순위와 최종 적용 상태를 제공하고 D가 표시 노드와 화면을 구현한다. B는 신호 인식 입력을 제공한다. D7에 기본 표시, D8에 DRS와 페널티 연결, D9에 부하 및 예외 검증을 완료한다. 표시 장치 오류는 주행 제어를 차단하지 않도록 비동기로 처리하고 관제에 보고한다.

| 시험 | 통과 조건 |
| --- | --- |
| DRS 자격과 활성 구분 | 자격만 있을 때 초록색 미점등, 실제 활성 시 초록색 |
| DRS 중 사람 또는 레드 | 초록색 해제, 최우선 정지 사유 표시 |
| SC와 그린 전환 | SC 표시 후 그린 해제 시 현재 상태로 복귀 |
| 페널티 계시 | 실제 정지 후 시작한 타이머와 LCD 일치 |
| 표시 입력 timeout | DRS 표시 해제, 상태 이상 표시와 관제 보고 |
| LED와 LCD 동시 실행 | 장치 오류와 제어 주기 지연을 기록하고 허용 범위 확인 |

LED와 LCD 동시 제어는 설치 이미지와 드라이버 버전에서 검증한다. 시연 완료 조건에 표시와 실제 주행 상태의 일치, 정지 우선 표시, 동시 출력 시 제어 지연 측정을 추가한다.

21 전면 LCD 랩타임 표시

정상 주행 화면에는 현재 랩의 경과시간을 가장 크게 표시하고, 로봇 ID와 순위, 진행 랩, 직전 랩타임과 베스트 랩을 함께 표시한다. 숫자 갱신은 기존 LCD 갱신 주기 안에서 수행하며, 경기 규칙 판단과 주행 제어를 기다리게 하지 않는다.

기본 화면 구성

상단: A 또는 B, 현재 순위 P1 또는 P2, LAP 1/3.

중앙: 현재 랩 경과시간 CURRENT 00:12.34.

하단: 직전 랩 LAST 00:28.45, 베스트 랩 BEST 00:27.81.

보조 상태: DRS READY 또는 DRS ON 등 현재 적용 상태. 첫 랩의 LAST와 BEST는 --:--.--로 표시한다.

계시와 랩 확정

경기 시작은 중앙 출발 승인 시각으로 통일한다. 첫 랩은 승인 시점부터 첫 유효 결승선 통과까지 계시하고, 다음 랩은 직전 유효 결승선 통과부터 계산한다. 출발 직후 결승선을 통과하는 이벤트는 체크포인트 순서가 충족되지 않았으면 랩으로 인정하지 않는다. 기록은 체크포인트와 진행 방향을 확인한 유효 통과에서만 확정한다.

옐로, 세이프티카, 사람 정지와 외부 페널티 중에도 경기 시계와 현재 랩 시계는 계속 흐른다. 정지 시간도 해당 랩 기록에 포함한다. 레드는 해당 경기 종료이므로 종료 시점에서 시계를 고정하고, 미완료 랩은 완주 기록이나 베스트 랩에 반영하지 않는다. 로봇별 정상 완주 시 최종 기록을 고정한다.

BEST는 해당 경기에서 완료한 유효 랩 중 최소 시간으로 갱신한다. 옐로와 SC가 포함된 랩도 기본안에서는 기록에 포함하되 이벤트 로그에 해당 상태를 남긴다. 새 경기 초기화 시 LAST와 BEST를 초기화하고, 이전 경기 결과는 관제 기록으로 보관한다.

표시 우선순위와 성능

사람 정지, 레드, 페널티, 오류 상황에서는 원인이나 페널티 남은 시간을 크게 표시하고 랩타임은 보조 영역으로 내린다. SC와 옐로에서는 해당 상태를 명확히 유지하면서 현재 랩 시간을 함께 보여준다. 정상 주행 복귀 시 현재 랩 중심 화면으로 돌아간다.

관제의 경기 관리자가 lap_start_time, last_lap_time, best_lap_time, race_elapsed와 유효성을 제공한다. LCD 표시용 단조 증가 타이머를 중앙 시각과 동기화하고, 로봇 간 시각 오차와 오래된 입력을 검사한다. 표시 정밀도 0.01초는 계측 정확도 0.01초를 보장하지 않는다. 화면은 초당 2~5회 갱신하는 초기안으로 시작한다.

검증 항목

유효 결승선 통과 시 현재 시간 초기화와 LAST 갱신, BEST 최소값 갱신, 사람 및 페널티 정지 중 계시 지속, 레드 종료 후 시간 고정, 첫 랩과 새 경기 초기화, 관제와 LCD 기록 일치를 확인한다. D7에 표시를 구현하고 D9에 전체 경기에서 검증한다.
