# 최신 요구: 사전 등록 지도와 현장 한계 측정

이 문서는 기존 정찰랩 필수 요구를 대체한다. 경기 중 정찰랩과 SLAM 지도 생성은 하지 않는다.
운영 전 SLAM 또는 별도 측량으로 만든 지도를 등록하고 경기에서는 localization을 사용한다.
기본 흐름: 지도 등록 → 위치 확인 → 출발 정렬 → 레이싱 → 기록/종료.

## 구현
- adaptive_map.py: 등록 점유 격자에 live 장애물을 별도 TTL 계층으로 반영, footprint 팽창, A* 우회 경로 생성, 경로가 없으면 오류로 정지 요청. 미지 공간은 차단한다.
- hardware_limits.py: 실측 속도·감속도·지연·여유 거리·횡가속·각속도로 속도 상한 계산, 코너 전 감속을 위한 후방 속도 제한 전파.
- tracking_node.py: verified 실측 limits 파일을 요구하며 경로 속도 프로파일을 실제 후보 명령에 적용한다.

## 연결 상태
adaptive_map은 순수 계산 모듈이다. 실시간 scan→map TF 변환, OccupancyGrid 구독, 우회 경로를 tracker로 넘기는 동작은 아직 연결되지 않았다. 따라서 현재 노드가 실물 변화에 즉각 회피한다고 주장할 수 없다.
A* 결과는 격자 경로이며 바로 고속 주행하지 않는다. 평활화 후 footprint 및 곡률을 재검사해야 한다.
TTL 만료는 장애물 철거의 증거가 아니다. 센서가 끊기면 최종 guard에서 정지해야 하며, 재관측으로 통행 가능 여부를 확인해야 한다.
벽 전체 이동처럼 localization을 훼손하는 변화는 정지 후 지도 재등록한다. 작은 변화는 live 계층으로 처리하며 원본 지도를 자동 덮어쓰지 않는다.

## 실측 설정 파일
limits_file JSON 형식:
```
{"verified": false, "limits": {"speed": null, "braking": null, "latency": null, "margin": null, "lateral_accel": null, "angular": null}}
```
값은 m/s, m/s², s, m, m/s², rad/s 단위다. 현장 기록과 검토 후 값을 채우고 verified=true로 바꾼다. 임의 수치로 실물 검증을 대신하지 않는다.
기존 tracking_node 실행 명령에 -p limits_file:=/absolute/measured_limits.json을 추가한다.
