# 평일 시뮬레이션 검증

현재 실행 명령, 합격 기준과 문제 해결 절차는 [단독 주행 실행 가이드](SIMULATION_RUNBOOK.md)에 있다. 아래는 단독 센서 통합 전 기준의 작업 기록이다.

기준: 사전 등록 지도, 경기 정찰랩 없음. 최고속도·제동·코너 한계는 토요일 실측 후 확정.

## 공통 자동 검증
```bash
python3 scripts/validate_weekday.py
```
60개 기본/지도/추종 테스트, 12개 별도 guard 테스트, 19개 모듈 예제, 10회 운동학 3랩 시험을 순서대로 실행한다. 하나라도 실패하면 중단한다. 이는 Gazebo와 실제 센서 연동 검증을 대체하지 않는다.

## 오늘 3시간
- 0~30분: 전원 같은 브랜치/커밋 확인, 대표 PC ROS Jazzy·Gazebo·공식 Pinky 모델 실행 상태 기록.
- 30~90분: A는 등록 지도/map server/localization, B는 scan/odom/TF/clock 기록, C는 경로와 속도 프로파일, D는 후보 명령→최종 guard 연결.
- 90~150분: Gazebo 저속 경로 추종과 센서/명령 단절 정지 시험. 모델 토픽과 frame은 실제 실행 결과로 확인한다.
- 150~180분: 실패 로그와 정확한 실행 명령 기록, 다음 수정 3개 선정.

## 내일 3시간
- 0~60분: 전날 실패 수정. 기존 테스트 재실행.
- 60~120분: 콘 추가, 통로 축소, 통로 완전 차단, scan 끊김, 위치 점프를 각각 시험.
- 120~160분: 장애물 없는 연속 3랩, 조건 변경 후 재실행. 랩시간·접촉·개입 기록.
- 160~180분: 실물 적용용 설정 목록과 토요일 측정표 준비.

## 완료 판정
| 환경 | 현재 상태 | 필요한 증거 |
|---|---|---|
| 순수 로직 | 자동 테스트 통과 | 실행 로그 |
| 간이 운동학 | 타원 10회 각 3랩 통과 | evidence/kinematic_laps.json |
| Gazebo | 미검증 | 모델 버전·world·launch·rosbag·영상 |
| ROS 우회 연결 | 미구현/미검증 | scan→map 변환, map 입력, 경로 교체와 guard 통합 |
| 실물 | 토요일 예정 | 실제 속도·정지거리·코너 오차·배터리 |

중요: 현재 adaptive_map은 경로 계산 모듈이며 tracking_node로 자동 연결되어 있지 않다. 이 연결이 완료되기 전에는 장애물 대응을 성공으로 기록하지 않는다.
limits_file은 실제 실측용과 시뮬레이션용을 별도 파일로 관리한다. 시뮬레이션 수치를 실물 검증값으로 재사용하지 않는다.
실패 기록에는 commit, 설정, 입력, 기대/실제 동작, 재현 명령, 영상/bag 위치를 포함한다.
